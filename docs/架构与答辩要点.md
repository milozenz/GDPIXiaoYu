# 广理职小鱼 · 架构与答辩要点

> 这份文档的每一条都对应仓库里真实的代码，文件名和函数名写在括号里，答辩时老师问"在哪"可以直接翻到。

## 1. 一句话和一张图

校园二手交易平台：**C 写服务器，C# 写 Windows 客户端，中间用自己设计的 TCP 协议**。

```
┌────────────────────────────┐        ┌───────────────────────────────────────┐
│ C# 客户端（WPF + MVVM）      │        │ C 服务器（每个连接一个线程）              │
│  Pages（界面）               │  TCP   │  core/server.c   连接、收发、鉴权         │
│   └ ViewModel（逻辑）        │ 长连接  │  core/router.c   命令分发表              │
│      └ IApiClient（接口）    │ ◀────▶ │  modules/*       user goods order chat  │
│         ├ TcpApiClient       │ 4字节长度│                  safety（内容安全）      │
│         └ FakeApiClient      │ + JSON │  core/db.c       SQLite（WAL，事务）     │
└────────────────────────────┘        │  core/words.c 敏感词 jev.c AI mail.c 邮件│
┌────────────────────────────┐  TCP   │  core/platform.c Windows/Linux 封装     │
│ 审核后台（ASP.NET Core 网页） │ ◀────▶ └───────────────────────────────────────┘
│  浏览器 ⇄ admin.* 命令        │              │ HTTPS              │ SMTP
└────────────────────────────┘        Jev 决策模型（AI 审核）  邮箱（验证码）
```

## 2. 通信协议（`docs/协议文档.md`）

| 问题 | 怎么解决 | 在哪 |
|---|---|---|
| TCP 是字节流，不知道一条消息在哪结束（粘包/半包） | 每条消息前加 **4 字节大端长度**，收满再解析；超过 8MB 直接断开 | `core/platform.c` 的 `net_recv_all`，`core/server.c` |
| 一个连接上同时发多个请求，回复怎么对上 | 请求带 `id`，回复原样带回，客户端按 id 匹配 | `TcpApiClient.CallAsync` |
| 服务器怎么主动通知（新私信、订单变化） | 同一条连接上发"推送"消息：没有 `id`，有 `push` 字段 | `core/push.h`，`TcpApiClient` 的 `MessageReceived`、`OrderUpdated` |
| 怎么发现对方掉线 | 客户端每 30 秒发 `sys.ping`；服务器 120 秒收不到任何消息就断开；客户端断线后自动重连 | `HeartbeatLoopAsync`、`ReconnectLoopAsync` |
| 回复和推送在不同线程同时发，会不会搅在一起 | 每个连接一把发送锁 | `core/server.c` 的 `send_lock` |
| 服务器在公网上，会不会被偷听 | 外面加一层 **TLS**：nginx 在 443 端口解密后转给只听本机的服务器，客户端用 `SslStream` 并校验证书（Let's Encrypt 免费证书） | `deploy/install-tls.sh`，`TcpApiClient.ConnectAsync` |

金额一律是**整数"分"**（不用浮点数，避免 0.1+0.2≠0.3）；时间一律是 Unix 秒。

## 3. 服务器

### 3.1 线程模型
主线程 `accept`，每来一个连接开一个线程（`thread_start`）；每个线程用**自己的数据库连接**，SQLite 开 **WAL 模式**，读写可以同时进行，写冲突时等 5 秒（`busy_timeout`）。

### 3.2 命令分发
`core/router.c` 里有一张 `ROUTES` 表：命令名 → 处理函数 → 要不要登录。收到 `goods.search` 就查表、校验 token、调 `goods_search`。**加一个新功能 = 表里加一行 + 写一个函数**。

### 3.3 数据库（`core/db.c`，14 张表）
交易：`users` `sessions` `categories` `goods` `goods_images` `orders` `messages` `favorites`；
内容安全：`email_codes`（验证码）`reports`（举报）`appeals`（申诉）`mod_cases`（审核案件）`review_jobs`（AI 审核队列）`blocked_logs`（被拦下的内容）。
外键打开，常用查询都有索引。表结构有版本号，版本不对的旧数据库会拒绝启动，不会悄悄用错。

**最关键的一个索引**：`idx_orders_goods_active`，是个**部分唯一索引**——同一件商品，"没被取消的订单"最多只能有一个。它是防超卖的**最后一道保险**。

### 3.4 防超卖和担保交易（`modules/order/order.c`）
下单函数 `order_create` 在一个 `BEGIN IMMEDIATE` 写事务里依次做：
1. 查商品（存在？不是自己的？在售？）
2. `UPDATE goods SET status='sold' … WHERE id=? AND status='on_sale'`，看 `sqlite3_changes`：不是 1 就说明被别人抢先了 → 回滚，返回 409
3. `UPDATE users SET balance=balance-? … WHERE balance>=?`，不是 1 → 余额不足 → 回滚，返回 402
4. 把商品标题、价格**快照**进订单（卖家以后改价，订单不变）
5. 提交；**提交成功之后**才给卖家发推送

订单状态机：

```
 在售 ──下单──▶ paid（已付款，钱由平台保管）
                 ├─ 卖家发货 ──▶ shipped ──买家确认收货──▶ completed（钱这时才打给卖家）
                 └─ 买家或卖家取消 ──▶ cancelled（钱退买家，商品重新上架）
```
每次状态变化都是 `UPDATE … WHERE status=旧状态`，看 `sqlite3_changes`，所以**同一个操作点两次，第二次一定失败**，不会重复入账。

实测：10 个人同时抢同一件商品，**1 人成功，9 人收到 409**。

### 3.5 安全
| 风险 | 做法 | 在哪 |
|---|---|---|
| 密码泄露 | 不存明文：`SHA256(32位随机盐 + 密码)`；注册要求 8–32 位且含数字、大写、小写 | `user.c` 的 `hash_password`、`registration_password_valid` |
| 撞库探测用户名 | 用户名不存在和密码错误返回同一句话 | `user_login` |
| SQL 注入 | **全部**参数化查询（`sqlite3_bind_*`），没有拼接用户输入 | 所有 `modules/*.c` |
| 路径穿越（图片名写成 `../../etc/passwd`） | 图片名只允许"32 位十六进制 + 固定扩展名" | `core/files.c` |
| 乱码/非法编码绕过长度检查 | 严格的 UTF-8 校验（拒绝非法字节、过长编码、代理对），长度按字符数算 | `text_valid` |
| 并发注册同名 | 不是"先查再插"，而是靠数据库唯一约束，冲突返回 409 | `user_register` |
| 余额溢出 | 入账时检查不超过 2^53−1 | `user_recharge`、`order.c` |
| token | 64 位随机十六进制，7 天有效，退出登录立即作废 | `user_login`、`user_logout` |

### 3.6 跨平台（`core/platform.c`）
网络（Winsock / POSIX 套接字）、线程（Win32 / pthread）、锁、随机数（`BCryptGenRandom` / `/dev/urandom`）都封装在一个文件里，业务代码里没有一行 `#ifdef _WIN32`。

### 3.7 内容安全（`modules/safety/safety.c`、`core/words.c`、`core/jev.c`）
分三层，越往后越慢、越准：
1. **敏感词库**（`words.c`）：字典树（Trie）一次扫完整段文字。扫之前先**归一化**：去掉空格和符号、全角转半角、大写转小写，所以"傻 逼""ＳＢ"这类变体也能命中；还有白名单（比如思政课教材的书名里有领导人名字，不能拦）。**一级词**直接拦下不发，**二级词**（骚扰威胁、诈骗引流）照常发出但提醒接收方
2. **AI 审核**（`jev.c`）：用 TypeSafe 的 Jev 决策模型。它不写文章，只回答选择题，**每个答案带概率**，正好用来做"有把握就自动处理，没把握交给人"：概率 ≥ 0.9 才自动处理
3. **人工审核**：AI 没把握的、调用失败的、用户的申诉，都进审核后台的"人工待审"；AI 自动处理过的进"已自动处理"，人工可以确认或撤销

几个设计点：
- **举报问两次 AI，而且互相独立**：① 这条消息本身是否明确违规（严，看不到举报理由，防止举报人"带节奏"）② 举报理由是否成立（宽）。只有 ① 能触发自动禁言
- **AI 审核不卡用户**：发商品、举报后马上返回，审核任务写进 `review_jobs` 表，由后台线程（`review_start`）每秒处理一轮；表在数据库里，服务器重启也不会丢；AI 调用失败最多重试 5 次，之后转人工（二级词私信只是提醒，失败就不再处理）；商品在 AI 出错时先上架，不让 AI 故障影响正常交易
- **屏蔽不是删除**：被屏蔽的消息原文还在库里，客户端只拿到"该消息因违规已被屏蔽"，管理员能看原文、能撤销；商品永远不删，只改状态
- **多个 AI 调用源**：配置里可以写多个（官方接口、OpenRouter），前一个失败换下一个；密钥只放在环境变量里，不进代码仓库

## 4. 客户端

### 4.1 分层（为什么这么分）
- **界面（XAML）** 只管长什么样；**ViewModel** 管逻辑和数据，不知道界面长什么样；两边靠**数据绑定**连起来 → 改界面不用动逻辑
- 界面和 ViewModel 只认 **`IApiClient` 接口**，有两个实现：`FakeApiClient`（内存里的假数据，规则和真服务器一样）和 `TcpApiClient`（真连服务器）。**开发界面时不需要服务器，联调时一行界面代码不改**
- `Navigator` 统一管页面跳转和页面切换动画；`AppServices` 放全局共享的东西

### 4.2 几个值得讲的细节
- **图片**：上传前缩到长边 1280 像素再转 JPG（几 MB 的照片变成一两百 KB）；显示时 `RemoteImage` 附加属性 + `ImageCache`，同一张图只下载一次
- **推送**：后台线程收到推送，经 `Ui.Run` 切回界面线程再改列表；聊天页实时追加气泡并标已读，订单详情页实时刷新状态
- **无限滚动**：首页滚到快到底自动加载下一页
- **乐观更新**：点收藏心形，界面先变，请求失败再变回来
- **动效**：统一在 `Services/Motion.cs`（淡入上滑、弹出）和 `Styles/Theme.xaml`（按钮按压、标签切换、卡片悬停），都在 0.1–0.3 秒
- **线上版 exe**：`dotnet publish -p:Online=true` 打包成一个自带 .NET 运行时的 exe，没有配置文件时默认连线上服务器（`Services/AppServices.cs` 里的 `#if ONLINE`）

### 4.3 审核后台（`client/XiaoYu.Admin`）
ASP.NET Core 写的网页，引用和客户端同一个 `XiaoYu.Core`：管理员登录后，后台为他开一条 `TcpApiClient` 连接，网页上的每个操作都变成一条 `admin.*` 命令。**后台自己不碰数据库**，"是不是管理员"由 C 服务器检查。网页是原生 JavaScript，不用框架。

| 风险 | 做法 |
|---|---|
| 别人冒充管理员发请求（跨站请求伪造） | 登录 Cookie 设 `SameSite=Strict`，改数据的请求还必须带自定义请求头 |
| 用户在昵称、私信里写脚本（XSS） | 用户内容一律当纯文本放进页面（`textContent`），不拼 HTML；再加内容安全策略（CSP）只允许本站脚本 |
| 猜管理员密码 | 同一 IP 15 分钟输错 5 次就暂停，所有 IP 加起来 30 次全部暂停 |
| Cookie 被脚本偷走 | `HttpOnly`（脚本读不到）+ `Secure`（只走 HTTPS） |

## 7. 可能被问到的问题

**Q：为什么不用 HTTP / WebSocket？** 想自己体会"分帧、粘包、心跳、推送"这些底层问题；而且需要服务器主动推送，长连接比轮询更合适。

**Q：SQLite 能支持多少人？** 写入是串行的（一个写事务一个时间），但我们每个事务都很短，WAL 模式下读不被阻塞。校园规模（几百人同时在线）够用；再大要换 MySQL/PostgreSQL。

**Q：密码为什么不用 bcrypt？** 我们用的是加盐 SHA-256，能防彩虹表，但对暴力破解不如 bcrypt/Argon2 慢。这是一个已知的取舍，换算法只需要改 `hash_password` 一个函数（并让旧用户下次登录时升级）。

**Q：传输加密了吗？** 加了。服务器在公网上，所以在 443 端口加了一层 TLS：nginx 负责加密解密（证书是 Let's Encrypt 的，自动续期），解密后转给只听本机的 C 服务器；客户端用 .NET 的 `SslStream`，按系统的信任链校验证书，证书不对就拒绝连接。C 服务器和协议一行没改，因为 TLS 是在 TCP 和我们的协议之间加的一层。审核后台和门户网站走 Cloudflare 的 HTTPS。

**Q：AI 判错了怎么办？** 只有概率 ≥ 0.9 才自动处理，其余交给人；自动处理也全部进"已自动处理"等人工复核，可以撤销；用户还可以申诉。测试里一条正常消息被恶意举报，AI 给了 0.35，没有自动处理，转给了人工。

**Q：钱是真的吗？** 不是，充值是模拟的。重点是演示"担保交易"的状态机和事务一致性。

**Q：怎么证明没有超卖？** 数据库层有部分唯一索引兜底，业务层有条件更新，测试里 10 个线程并发抢购只有 1 个成功，对账后买家余额合计只少了一份货款。

## 8. 已知局限（老师问到时诚实回答）

- 密码哈希不是专用慢哈希（加盐 SHA-256，不是 bcrypt/Argon2）
- 图片存在服务器本地磁盘，没有 CDN、没有去重
- 分页用 OFFSET，翻到很深的页会变慢
- token 没有刷新机制，7 天后要重新登录
- 没有评价系统
- AI 审核依赖外部服务（OpenRouter），断网时退化为"先放行、转人工"
- exe 没有代码签名，Windows 会提示"已保护你的电脑"
